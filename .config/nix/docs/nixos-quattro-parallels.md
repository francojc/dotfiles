# NixOS Quattro Lab Plan and Parallels Guide

> **Status:** proof of concept. This adds a separate `aarch64-linux` NixOS host to the existing flake. It does not alter either nix-darwin host.

## Goal

Create an Apple-Silicon-friendly NixOS desktop lab that recreates the useful parts of Omarchy Quattro without porting Omarchy or its Arch/x86_64 assumptions:

- Hyprland for a keyboard-first Wayland compositor and workspaces;
- Quickshell for a single, small desktop-shell process;
- a coherent theme shared with the existing Ghostty/terminal/editor configuration;
- lock, idle, portal, launcher, clipboard, notification, screenshot, and audio helpers;
- a rollbackable, flake-based configuration suitable for a Parallels Desktop ARM guest.

## Current flake integration

The POC uses the repository's established host model:

- `lib/systems.nix` already declares `aarch64-linux`.
- `flake.nix` builds `nixosConfigurations` from host definitions.
- `home/themes/themes.nix` passes the selected palette as the `theme` module argument.
- `nixos-quattro` selects the existing `ayu` theme, imports the shared NixOS baseline, and adds a Hyprland/Quickshell profile.

New POC files:

```text
hosts/nixos-quattro/default.nix       # aarch64 host declaration
hosts/nixos-quattro/configuration.nix # guest-specific boot/user policy
profiles/nixos/quattro.nix                # system Hyprland/portal/greetd packages
home/quattro.nix                          # Hyprland bindings, idle policy, Quickshell panel
```

The `shell.qml` generated by Home Manager at `~/.config/quickshell/shell.qml` is now a meaningful vertical slice: it uses Quickshell's Hyprland integration for live workspaces, uses `SystemClock` rather than spawning `date`, and exposes small typed IPC commands (`qs ipc call bar workspace 2`, `qs ipc call bar toggle`). The next iterations should add tray, notifications, media, power, and a launch/menu UI one feature at a time.

## POC feature map

| Quattro concept | This POC | Next iteration |
|---|---|---|
| Tiling/window workflow | Hyprland keybindings, workspaces, focus and move commands | app rules, scratchpads, monitor-specific layout |
| Single shell process | Quickshell starts from Hyprland | workspaces, tray, notification daemon, menu and IPC |
| Themed desktop | Reuses host-selected theme colors | declarative wallpaper/font/spacing tokens |
| Launcher | Fuzzel (`Super+Space`) | Quickshell launcher panel and IPC |
| Notifications | SwayNotificationCenter | Quickshell notification server once its UX is designed |
| Lock/idle | Hyprlock + Hypridle | visual lock theme and suspend policy |
| Desktop plumbing | portals, PipeWire, NetworkManager applet, clipboard history | host/guest sharing and workflow-specific widgets |

## Parallels Desktop setup

### 1. Create an ARM guest

On either Apple Silicon Mac:

1. In Parallels, create a new VM and choose **Install Windows or another OS from a DVD or image file**.
2. Select a current **NixOS `aarch64-linux` installer ISO**. The official NixOS minimal `aarch64-linux` image works, as does Determinate Systems' installer ISO (`https://install.determinate.systems/nixos-iso/stable/aarch64-linux`), which pre-enables flakes and ships Determinate Nix and `fh`. Either flavor is worth the same here: the ISO is only the bootstrap environment and the installed guest comes from `nixos-install --flake .#nixos-quattro`. Do not use an x86_64 ISO/image.
3. Configure the VM with an initial 4 vCPU, 8 GiB RAM, and 60–80 GiB disk. These values are starting points for a graphical lab, not requirements.
4. Enable Parallels 3D acceleration before installing. Hyprland needs an accelerated virtual GPU to be useful.
5. Use NAT initially. The shared NixOS baseline enables the Tailscale service; authenticate it only after the first successful graphical login if remote access is wanted.

Keep macOS as the host desktop. This guest is a contained Wayland lab; it does not replace macOS's compositor or security model.

### 2. Partition and install NixOS

Boot the ISO, connect networking, and partition the VM's primary disk. **The following commands erase the selected disk.** Confirm its name with `lsblk`; Parallels can expose a virtio disk as `/dev/vda`, but do not assume it.

The POC host expects:

- an EFI System Partition mounted at `/mnt/boot`;
- an ext4 root filesystem with label `nixos`, mounted at `/mnt`.

A representative sequence, **after confirming the correct disk**, is:

```bash
sudo -i
export DISK=/dev/vda   # replace only after verifying with lsblk
parted "$DISK" -- mklabel gpt
parted "$DISK" -- mkpart ESP fat32 1MiB 512MiB
parted "$DISK" -- set 1 esp on
parted "$DISK" -- mkpart primary ext4 512MiB 100%
mkfs.fat -F 32 -n EFI "${DISK}1"
mkfs.ext4 -L nixos "${DISK}2"
mount /dev/disk/by-label/nixos /mnt
mkdir -p /mnt/boot
mount /dev/disk/by-label/EFI /mnt/boot
```

Clone this repository into the installed root, then install the guest configuration:

```bash
mkdir -p /mnt/home/jeridf
git clone https://github.com/francojc/dotfiles.git /mnt/home/jeridf/.dotfiles
cd /mnt/home/jeridf/.dotfiles/.config/nix
nixos-install --flake .#nixos-quattro
reboot
```

The checkout is copied in by the installer as root-owned. After the first login, make it editable by the configured account:

```bash
sudo chown -R "$USER":users ~/.dotfiles
```

If the installer reports hardware-specific requirements, use `nixos-generate-config --root /mnt` to inspect them and add only the needed options in a local host override. Do not overwrite the repository's shared modules blindly.

### 3. First boot and host integration

1. Log in at the `tuigreet` prompt. It starts `Hyprland`.
2. Open Ghostty with `Super+Return`; use `Super+Space` for Fuzzel.
3. Confirm Wayland and renderer state:

   ```bash
   hyprctl systeminfo
   wayland-info
   qs --help
   ```

4. If the session is black, laggy, or Hyprland reports a renderer issue, power off the VM and confirm Parallels 3D acceleration is enabled before changing Nix configuration.
5. Treat clipboard integration, dynamic resolution, shared folders, camera/microphone, and suspend as host-integration enhancements. Verify each separately; none is required for the POC to prove the NixOS desktop configuration.

## Validation plan

1. Format all Nix source with `nix fmt`.
2. Evaluate the new host from an `aarch64-linux` evaluator or the guest itself:

   ```bash
   nix eval .#nixosConfigurations.nixos-quattro.config.system.build.toplevel.drvPath
   ```

3. On the installed guest, build before activation:

   ```bash
   sudo nixos-rebuild build --flake .#nixos-quattro
   ```

4. Activate only after the build succeeds:

   ```bash
   sudo nixos-rebuild switch --flake .#nixos-quattro
   ```

5. Verify: `hyprctl monitors`, Quickshell panel presence, `loginctl`, `systemctl --user status hypridle`, clipboard history, launcher, lock, audio keys, and screenshot command.
6. Roll back a failed activation from a TTY with `sudo nixos-rebuild switch --rollback`, or select the earlier systemd-boot generation.

## Deliberate non-goals and risks

- This POC does not copy Omarchy code, branding, package scripts, or x86_64-only dependencies.
- It does not claim that every Omarchy Quattro component has a NixOS equivalent yet.
- Quickshell development moves quickly. Keep custom QML narrow and validate it in the ARM guest before expanding it.
- VM graphics behavior is a Parallels/virtual-GPU concern. Avoid diagnosing it as a NixOS configuration issue until `hyprctl systeminfo` has been checked.
- The current guest has no disk encryption or production backup policy. Add those only after the desktop loop is stable.

## Incremental development plan

1. **Baseline (this PR):** add host, Hyprland, portal/lock/idle plumbing, themed Quickshell panel, and installation/rollback guide.
2. **Shell observability:** add a focused Quickshell workspace indicator and tray; validate reload behavior.
3. **Interaction:** add Quickshell IPC and a launcher/menu surface; preserve Fuzzel as a fallback until proven reliable.
4. **Service consolidation:** move notifications/media/network widgets into Quickshell only after each component matches the fallback behavior.
5. **Host polish:** add explicitly tested Parallels sharing/resolution/clipboard guidance and per-Mac display overrides without changing the Darwin systems.
